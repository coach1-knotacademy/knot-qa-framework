# S7 · Tu CP en Gherkin, sobre las capas del framework

Hoy no hay código nuevo que completar: el trabajo es **escribir el caso como escenario** y **decir qué capa ejecuta cada paso**. Gherkin es el CP de siempre con otra sintaxis: lo firma negocio antes de automatizar y no cambia cuando cambia la pantalla.

| Pieza | En una frase | Dónde verla |
|---|---|---|
| **El escenario** | Dado (la precondición), Cuando (lo que hace el cliente), Entonces (el esperado, con el dato). El ID del ALM en la etiqueta | [`especificaciones/recargas.feature`](../especificaciones/recargas.feature) |
| **La prueba** | Cada paso es un `test.step` con el mismo texto; el reporte HTML muestra el escenario paso a paso | [`tests/recargas/CP-101-gherkin.spec.ts`](../tests/recargas/CP-101-gherkin.spec.ts) |
| **La tarea** | El «Cuando» es una tarea de Screenplay que usa el Page Object por dentro: los dos patrones se combinan | [`src/screenplay/recargas/RecargarDesdeLaPantalla.ts`](../src/screenplay/recargas/RecargarDesdeLaPantalla.ts) |
| **El revisor** | Señala clics, localizadores, claves, esperas fijas, falta de ID y «Entonces» sin dato | `npm.cmd run revisar-escenarios` · o en el navegador: [actividades de la S7](https://coach1-knotacademy.github.io/knot-qa-framework/actividades-s7.html) |

## La práctica (en salas)

1. **Tramo 1 · el escenario.** Cada sala escribe el escenario de su CP en `especificaciones/recargas.feature` (o en el revisor de las actividades): Sala 1 CP-102, Sala 2 CP-103, Sala 3 CP-104, Sala 4 CP-105, Sala 5 CP-106. **Terminado:** el revisor no marca errores → en el chat, «Sala X: 0 errores».
2. **Tramo 2 · el mapeo.** Para cada paso: qué capa lo ejecuta y con qué pieza (tarea, página, fábrica, `expect`, configuración). **Terminado:** «Sala X: 6 de 6».

Los CP están en las actividades de la S6 y la S7 (CP-101 a CP-106, del Banco Demo). **Nunca** se usan casos del ALM del banco.

## Para correrlo en tu equipo

```powershell
npx.cmd playwright test -g "CP-101" --project=recargas
npm.cmd run reporte
npm.cmd run revisar-escenarios
```

En el reporte, abre la prueba: los cuatro pasos aparecen con el texto del escenario.

## Lo que no entra hoy (a propósito)

- **playwright-bdd o Cucumber**, que leen el `.feature` directamente: necesitan instalar paquetes. En un equipo con Node es el paso siguiente; la idea es la misma.
- **Esquema del escenario** (`Esquema del escenario` + `Ejemplos`): es la S8, una prueba con muchos datos.
- **Antecedentes** y *hooks*.

La solución de la práctica queda en la etiqueta `s07-solucion`.
