Lo preciso · tres correcciones de la S7

Se oyóLo preciso
Las esperas
«El expect espera 30 segundos.»		→ El expect sobre un localizador reintenta hasta 5 segundos; 30 es el límite de toda la prueba. Los clics esperan a que el botón se pueda usar, dentro de esos 30. (playwright.dev/docs/test-timeouts)
El «Y» en el Cuando
«El «Y» en el Cuando hacía fallar la prueba.»		→ El «Y» es para leer mejor. Cucumber no mira la palabra; los pasos corren en orden, uno por uno, y el «Y» no cambia ninguna espera. (cucumber.io/docs/gherkin/reference)
El Entonces sin dato
«En el Entonces las dos eran correctas.»		→ Solo la A, la que tiene el dato («ve el mensaje «El celular debe tener 10 dígitos y empezar por 3»»). Un «Entonces» que no se puede reprobar («el sistema responde correctamente») no es un esperado.

En QA, un error que se corrige a tiempo es un hallazgo; uno que se esconde llega a producción.

foto o video

innerText espera a que aparezca el elemento y le toma una foto. toHaveText sigue mirando hasta que el texto sea el esperado: es un video. Para el comprobante, que ya no cambia, la foto sirve (así lo hace PaginaRecargas.esperarResultado); para el saldo, que se mueve, va el video.

Esquema del escenario y Data Driven Testing

El problema que ya sufrías a mano
El CP-103 y el CP-104 se prueban con varios datos. Escribir una prueba por dato es copiar y pegar: cuando cambia un paso, hay que arreglarlo en diez lugares, y negocio no ve de un vistazo qué datos se probaron.
La idea, en una frase
Los pasos se escriben una vez con <marcadores>; cada fila de la tabla Ejemplos es una prueba. En Playwright, un for sobre una lista de la fábrica crea un test() por fila, con un título único que lleva el dato.
Sus partes, en el repo
especificaciones/recargas-datos.feature (los Esquemas) · src/datos/fabricaDeRecargas.ts (rechazosPorMonto(), las filas con nombre) · tests/recargas/CP-104-limites.spec.ts (el for con título único y @CP-104).
Sí, cuando
La regla es la misma y cambia el dato: límites, operadores, formatos, tipos de cliente. Y negocio quiere ver la lista de casos.
No, cuando
Las filas siguen caminos distintos (una pide código y otra no) o tienen otro tipo de resultado: eso es otro Esquema. Ni datos aleatorios que nadie puede repetir.
La frase para tu líder
La tabla es lo que firma negocio y cada fila es una línea del reporte. Agregar un caso es agregar una fila, no una prueba.
Cómo pedírselo a la IA
«Convierte este escenario en un Esquema del escenario con Ejemplos: pasos con <marcadores>, una columna por dato, el dato en el título y 3 filas que pasen por los mismos pasos (incluye el borde). Si una fila cambia el resultado, sepárala en otro Esquema y dime por qué.»

la regla de los Ejemplos

Mismos pasos, otro dato, el mismo tipo de «Entonces». Si una fila cambia el camino o el resultado, es otro Esquema.

el for de tests/recargas/CP-104-limites.spec.ts

for (const rechazo of fabricaDeRecargas.rechazosPorMonto()) {
  test(`CP-104 · ${pesos(rechazo.monto)} → «${rechazo.mensaje}»`, { tag: '@CP-104' }, async ({ cliente }) => {
    // Los pasos son los del Esquema, llenados con esta fila: así se leen en el reporte.
    await test.step(`Dado que Ana tiene la sesión abierta y ${pesos(SALDO_INICIAL)} en Ahorros`, async () => {
      await cliente.iniciarSesion(usuarios.ana);
      expect(await cliente.saldoDeAhorros()).toBe(SALDO_INICIAL);
    });

    const respuesta = await test.step(`Cuando recarga ${pesos(rechazo.monto)} a un celular Claro ${CELULAR}`, async () => {
      return cliente.recargar(fabricaDeRecargas.valida({ monto: rechazo.monto, numero: CELULAR, operador: 'Claro' }));
    });

    await test.step(`Entonces ve el mensaje «${rechazo.mensaje}»`, async () => {
      // 400 = el banco rechazó la recarga. El texto de "error" es el mismo que la pantalla le muestra al cliente.
      expect(respuesta.estado).toBe(400);
      expect(respuesta.datos.error).toBe(rechazo.mensaje);
    });

    await test.step(`Y su saldo de Ahorros sigue en ${pesos(SALDO_INICIAL)}`, async () => {
      expect(await cliente.saldoDeAhorros()).toBe(SALDO_INICIAL);
    });
  });
}

Un test() por fila de la fábrica, con el dato en el título y la etiqueta @CP-104: cada fila tiene su línea en el reporte.

el error provocado

Se quita el monto del título: las filas de $100.001 y $150.000 quedan con el mismo nombre (las dos dicen «La recarga máxima es $100.000») y Playwright se niega a correr: no corre ninguna prueba («duplicate test title»). El título único no es estética: es lo que hace que cada fila tenga su línea en el reporte.
