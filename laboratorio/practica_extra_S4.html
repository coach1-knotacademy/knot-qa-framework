Ronda 1 · Vida diaria

Sin código. Si fallas aquí, piensa en la pregunta de cada letra.

1¿Qué letra se rompe?

El mismo funcionario de la oficina abre cuentas, aprueba créditos y hace el arqueo de caja. Cada vez que Auditoría cambia el arqueo, hay que volver a capacitarlo en todo y revisar que no se le olvidó cómo abrir cuentas.

Tres jefes distintos (comercial, riesgo y auditoría) piden cambios a la misma persona. Es la S: una sola razón para cambiar. «Las razones son personas».

2¿Qué letra se rompe?

Para recibir pagos con QR, el almacén tuvo que desarmar el datáfono que ya cobraba con tarjeta, modificarlo y volver a certificar también los pagos con tarjeta.

Agregar algo nuevo obligó a abrir lo que ya funcionaba y a repetir su certificación: regresión. Con la O, el QR sería un medio de pago nuevo que se conecta al lado.

3¿Qué letra se rompe?

El formulario único de apertura le exige a una persona natural «Razón social», «NIT» y «Representante legal». Ella escribe «No aplica» tres veces.

El formulario (la interfaz) es demasiado grande para este cliente. Cada «No aplica» es un método que la clase no debería estar obligada a tener, como en PaginaSaldos del reto 4.

4¿Qué letra se rompe?

«Cualquier tarjeta del banco sirve en el cajero». La tarjeta de puntos tiene el mismo chip; el cajero la acepta y responde «operación no soportada».

Dice ser una tarjeta (la hija), pero no cumple lo que promete la madre. Quien la usa se entera ya frente al cajero; en código, en plena ejecución.

5¿Qué letra se rompe?

La lámpara viene soldada al cableado. Para saber si funciona hay que instalarla, y si no prende no sabes si falló la lámpara o la luz de la casa.

Depende de una casa concreta, no de una forma (un enchufe). Es el new ClienteHttp dentro de la lógica: para probarla necesitas el banco prendido y, si falla, no sabes de quién es la culpa.

6¿Qué letra se rompe?

La calculadora de la oficina suma y resta. En cinco años nadie ha pedido otra operación. Alguien propone rehacerla con «plugins para operaciones futuras».

No se rompe ninguna. Crear un punto de extensión sin cambios a la vista es sobrediseño (YAGNI). La O se aplica donde ya hubo cambios o donde vienen.

Ronda 2 · Código de juguete

Clases pequeñas, sin Playwright.

7¿Qué letra se rompe?

¿Qué se rompe aquí?

class Usuario {
  validarClave(c: string) { … }
  enviarCorreoBienvenida() { … }
  guardarEnBaseDeDatos() { … }
}

Tres razones de cambio: la política de claves (Seguridad), el texto del correo (Mercadeo) y las tablas (base de datos). Tres personas distintas tocan la misma clase.

8¿Qué letra se rompe?

Mañana llega el nivel «platino».

function descuento(nivel: string, total: number) {
  if (nivel === 'oro') return total * 0.2;
  if (nivel === 'plata') return total * 0.1;
  return 0;
}

Cada nivel nuevo obliga a abrir la función y a volver a probar oro y plata. Es el mismo switch de calcularCosto; la salida es una regla por nivel y un registro.

9¿Qué letra se rompe?

¿Qué se rompe aquí?

class Archivo {
  leer() { … }
  escribir(texto: string) { … }
}
class ArchivoSoloLectura extends Archivo {
  escribir(): void { throw new Error('Solo lectura'); }
}

Quien recibe un Archivo confía en poder escribir, y la hija rompe esa promesa en ejecución. Si no puede escribir, no «es un» Archivo que escribe: la madre común debería tener solo leer().

10¿Qué letra se rompe?

¿Qué se rompe aquí?

interface Impresora {
  imprimir(): void;
  escanear(): void;
  enviarFax(): void;
}
class ImpresoraBasica implements Impresora {
  imprimir() { … }
  escanear()  { throw new Error('No aplica'); }
  enviarFax() { throw new Error('No aplica'); }
}

La clase no hereda comportamiento de nadie: la obligan a firmar un contrato demasiado grande. Se parte en Imprime, Escanea y EnviaFax. Si pensaste en la L, el síntoma es el mismo, pero aquí la causa es la interfaz gorda.

11¿Qué letra se rompe?

¿Qué se rompe aquí?

class ReporteVentas {
  private bd = new MySqlConexion('prod-db:3306');
  total() {
    return this.bd.consultar('SELECT SUM(valor) FROM ventas');
  }
}

La lógica crea su propia conexión, con el servidor escrito adentro: no se puede probar sin la base de producción. Que reciba algo que cumpla «consulta ventas» y que el new quede afuera.

12¿Qué letra se rompe?

¿Qué se rompe aquí?

class Calculadora {
  sumar(a: number, b: number) { return a + b; }
  restar(a: number, b: number) { return a - b; }
  multiplicar(a: number, b: number) { return a * b; }
}

Nada. Son tres métodos con una sola razón de cambio: la aritmética. La S no cuenta métodos; si marcaste S, caíste en el malentendido más común.

Ronda 3 · En pruebas automatizadas

El código que se ve en un framework real.

13¿Qué letra se rompe?

El archivo de ayudas del framework:

// helpers.ts
export async function login(page: Page, u: string, c: string) { … }
export function cedulaAleatoria(): string { … }
export function formatoPesos(n: number): string { … }
export async function crearIncidenteJira(titulo: string) { … }

Cuatro dueños en un archivo: la pantalla de login, los datos de prueba, el formato regional y la herramienta de incidentes. Es el AyudanteTodo del reto 1 con otro nombre.

14¿Qué letra se rompe?

¿Qué se rompe aquí?

test('saldo', async () => {
  const navegador = await chromium.launch();
  const page = await navegador.newPage();
  await page.goto('http://10.20.30.40:8080/');
  // …
});

La prueba crea su navegador y deja escrito el ambiente. Con async ({ page }), Playwright le pasa el navegador (fixtures), y con baseURL el ambiente sale de la configuración.

15¿Qué letra se rompe?

Las pruebas de documentos validan el formato con un switch (tipoDocumento) dentro de cada prueba: CC, CE y NIT. Llega el PPT (Permiso por Protección Temporal) y hay que abrir el switch en 9 pruebas.

Lo nuevo obliga a abrir 9 pruebas que ya funcionaban. Un validador por tipo de documento y un registro: el PPT es una pieza más.

16¿Qué letra se rompe?

Una madre para todas las páginas:

class PaginaBase {
  constructor(protected page: Page) {}
  async salir() {
    await this.page.getByRole('button', { name: 'Salir' }).click();
  }
}
class PaginaLogin extends PaginaBase {}  // en el login no hay «Salir»

La madre promete salir() y el login no lo puede cumplir: paginaLogin.salir() espera el botón hasta que se acaba el tiempo de la prueba y falla. Es el reto C de la S3: salir() va en una madre intermedia, PaginaConSesion.

17¿Qué letra se rompe?

El servicio de tasas es de solo lectura.

class ClienteTasas implements ClienteApi {
  async listar() { return this.get('/tasas'); }
  async crear()      { throw new Error('No aplica'); }
  async actualizar() { throw new Error('No aplica'); }
  async borrar()     { throw new Error('No aplica'); }
}

La interfaz obliga a tener crear, actualizar y borrar en un servicio que solo se consulta. Se parte en ConsultaTasas y AdministraTasas.

18¿Qué letra se rompe?

PaginaTransferenciaInternacional extends PaginaTransferir. Su transferir() exige además un código SWIFT y, si no llega, lanza error. Las pruebas que usaban PaginaTransferir con origen, destino y monto empiezan a fallar cuando reciben la internacional.

La hija exige más que la madre. Quien la usa como una PaginaTransferir no sabe que debe mandar el SWIFT. Una hija puede pedir lo mismo o menos, nunca más.

Ronda 4 · Matices y trampas

Aquí está la diferencia entre saberse las letras y entenderlas.

19¿Qué letra se rompe?

PaginaTransferir tiene seleccionarOrigen(), escribirDestino(), escribirMonto(), confirmar() y leerComprobante().

No se rompe ninguna. Es una pantalla con una razón de cambio. Tener muchos métodos no viola la S.

20¿Qué letra se rompe?

Agregaste ReglaNomina y tuviste que añadir una línea en reglasDelBanco(). ¿Rompiste la O?

No. reglasDelBanco() es el lugar donde se arman las piezas, y es normal que cambie. No tocaste ReglaAhorros, ReglaCorriente, RegistroDeReglas ni las pruebas viejas: por eso la regresión es solo Nómina.

21¿Qué letra se rompe?

cuatroPorMil usa Math.round por dentro. Alguien propone inyectarle un Redondeador «para cumplir la D».

Math.round es rápido, da siempre lo mismo y no depende del ambiente. Inyectarlo no te deja probar nada nuevo: es sobrediseño. Se inyecta lo externo, lo lento o lo que no da siempre lo mismo.

22¿Qué letra se rompe?

esHorarioBancario() usa new Date() por dentro. Su prueba pasa a las 10 a. m. y falla en la corrida nocturna.

La función crea su propia dependencia: el reloj. Que reciba la hora o un reloj, como Bitacora: la prueba le pasa una hora fija y da lo mismo correrla a cualquier hora.

23¿Qué letra se rompe?

Cuenta.retirar(monto) acepta cualquier monto positivo. CuentaCajero extends Cuenta solo acepta múltiplos de $10.000.

La hija exige más que la madre (una precondición más fuerte). El código que retiraba $25.500 de una Cuenta se rompe cuando recibe una CuentaCajero.

24¿Qué letra se rompe?

ResumenDeCuentas recibe un Cliente por el constructor, pero Cliente tiene 14 métodos y el doble de la prueba los implementa todos con «no implementado». El resumen usa 2.

La D está bien: recibe una abstracción. El problema es su tamaño: la interfaz debería tener lo que necesita quien la usa. Así, el doble queda con 2 métodos, como el ClienteFalso del reto 5.

Explícalo tú

La prueba más dura: si lo puedes explicar con tus palabras, lo tienes. Dilo en voz alta y después abre la respuesta modelo.

1Explica la S a alguien de pruebas manuales sin decir «clase».

Piensa en tu matriz de casos en Excel. Si en la misma hoja tienes los casos, los datos de prueba y el resumen que pide gerencia, cada vez que gerencia cambia el resumen te arriesgas a dañar los casos. Una hoja por dueño: si cambia el resumen, solo tocas la hoja del resumen.

2¿Por qué la O reduce la regresión? Dilo con números.

Con el switch, agregar Nómina toca la función por la que pasan los tres tipos: hay que volver a probar 3. Con reglas se agrega una pieza: se prueba 1 y las otras 2 ni se abren. Con 10 tipos de cuenta son 11 contra 1.

3Da un ejemplo de la L sin usar la palabra «herencia».

Un doble de prueba que dice ser el cliente del banco pero devuelve los saldos en centavos. Nada falla, pero los totales salen 100 veces más grandes. Todo lo que dice cumplir un contrato tiene que cumplirlo completo.

4¿En qué se diferencian la S y la I?

La S mira una clase desde adentro: ¿por cuántas razones cambia? La I mira una interfaz desde quien la usa: ¿lo obligo a conocer cosas que no usa? Una clase puede cumplir la S y aun así implementar una interfaz gorda.

5¿La D, la inyección de dependencias y los fixtures son lo mismo?

No. La D es el principio: la lógica depende de una abstracción y no de una pieza concreta. La inyección es una técnica para cumplirla: pasar la pieza desde afuera, por ejemplo por el constructor, como ResumenDeCuentas. Los fixtures de Playwright son inyección: la prueba pide page y Playwright se la pasa.

6¿Cuándo NO aplicarías SOLID?

Cuando el código es pequeño, no ha cambiado y no hay cambios pedidos: un switch estable de dos casos, un script de una sola vez, una prueba exploratoria. Primero lo simple (KISS); el principio entra cuando aparece el dolor, la tercera vez (regla de tres).

La prueba que crece: de espagueti a SOLID en seis pasos

La misma prueba de transferencia, mejorada una letra a la vez. Cada paso responde a un dolor concreto que trae el paso anterior. Es un ejemplo simplificado (sin OTP); donde dice «así está en el repo», es código real.

  1. 0

    El espagueti

    Lo que casi todos escribimos la primera vez. Funciona, y ese es el problema: funciona hasta el primer cambio.

    test('transferir desde Ahorros', async () => {
  const navegador = await chromium.launch();
  const page = await navegador.newPage();
  await page.goto('https://qa.banco.local/');
  await page.fill('#usuario', 'ana');
  await page.fill('#clave', '1234');
  await page.click('#entrar');
  await page.click('text=Transferir');
  await page.fill('#monto', '50000');
  await page.click('#confirmar');
  const tipo = 'Ahorros';
  const costo = tipo === 'Ahorros' ? 200 : 2200;
  await expect(page.locator('#costo')).toHaveText(String(costo));
  await page.screenshot({ path: 'evidencia.png' });
  await navegador.close();
});

    Qué duele: Cambian el id del campo usuario y hay que tocar las 40 pruebas que hacen login. El costo está calculado a mano y copiado en cada prueba.

  2. S

    Cada cosa con su dueño

    Las pantallas van a sus páginas (la S3) y la regla del costo vive en un solo lugar. La prueba queda leyéndose como un caso.

    const login = new PaginaLogin(page);
const transferir = new PaginaTransferir(page);

await login.abrir();
await login.ingresar('ana', '1234');
await transferir.abrir();
await transferir.transferir({ origen: 'Ahorros', destino: '123', monto: 50_000 });
await expect(transferir.comprobante).toBeVisible();
expect(cuatroPorMil(50_000)).toBe(200);   // la regla, en un solo lugar

    Qué ganaste: Si cambia el login, se toca un archivo. Pero llega Nómina…

  3. O

    Llega Nómina

    El costo depende del tipo. Con un if encadenado, cada tipo nuevo abre la lógica; con reglas, cada tipo es una pieza y los casos son una lista.

    Cada tipo abre la lógica

    const costo =
  tipo === 'Ahorros'   ? cuatroPorMil(monto) :
  tipo === 'Corriente' ? cuatroPorMil(monto) + 2_000 :
  0;   // ¿Nómina? ¿y la próxima?

    Cada tipo es una regla; cada caso, una fila

    const reglas = reglasDelBanco();
const esperado: Record<string, number> =
  { Ahorros: 200, Corriente: 2_200, Nómina: 0 };

for (const tipo of Object.keys(esperado)) {
  test(`costo desde ${tipo}`, () => {
    expect(reglas.costo(tipo, 50_000)).toBe(esperado[tipo]);
  });
}

    Qué ganaste: Un tipo nuevo es una regla más y una fila más. Ahorros y Corriente no se vuelven a abrir.

  4. L

    Aparece la pantalla de consulta

    Alguien quiere reutilizar saldoDe y hace que la consulta herede de la transferencia. La suite nocturna recorre todas las páginas que «saben transferir».

    Hereda para reutilizar

    class PaginaConsulta extends PaginaTransferir {
  async transferir(): Promise<void> {
    throw new Error('No aplica');
  }
}
for (const p of paginas) await p.transferir(datos);
// 💥 a las 2 a. m., con la consulta

    Una madre con lo que de verdad comparten

    abstract class PaginaDeCuentas {   // abrir(), saldoDe()
}
class PaginaTransferir extends PaginaDeCuentas {
  // + transferir()
}
class PaginaConsulta extends PaginaDeCuentas {}
// meterla en la lista de las que transfieren ya no compila

    Qué ganaste: El error pasó de la madrugada al editor. En el reto 3 se llaman PaginaTransferencia, PaginaConsulta y PaginaDeCuentas.

  5. I

    La ayuda pide solo lo que usa

    Se escribe una función para verificar saldos en varias pruebas. Si pide la interfaz gigante, cualquier doble necesita 8 métodos.

    Pide el contrato de 8 métodos

    async function verificarSaldo(
  p: PaginaDelBanco, cuenta: string, esperado: string) {
  expect(await p.saldoDe(cuenta)).toBe(esperado);
}

    Pide solo la capacidad que usa

    async function verificarSaldo(
  p: ConsultaSaldos, cuenta: string, esperado: string) {
  expect(await p.saldoDe(cuenta)).toBe(esperado);
}
// sirve con PaginaSaldos, con PaginaConsulta o con
// { saldoDe: async () => '$ 1.000' }

    Qué ganaste: La función sirve para más casos y se prueba con un doble de una línea.

  6. D

    La prueba recibe lo que necesita

    Ya no hay chromium.launch() ni new PaginaLogin en cada prueba: las arman los fixtures. Y la lógica del resumen se prueba sin banco.

    En los fixtures (así está en el repo)

    // src/soporte/fixtures.ts
paginaLogin: async ({ page }, usar) => {
  await usar(new PaginaLogin(page));
},

// la prueba solo pide:
test('transferir desde Ahorros',
  async ({ paginaLogin, paginaTransferir }) => { … });

    La lógica, sin navegador ni banco

    const resumen = new ResumenDeCuentas(new ClienteFalso([
  { numero: '001', tipo: 'Ahorros',   saldo: 100_000 },
  { numero: '002', tipo: 'Corriente', saldo:  50_000 },
]));
expect(await resumen.saldoTotal(usuarios.ana)).toBe(150_000);

    Qué ganaste: Cambiar de ambiente o de navegador ya no toca pruebas, y el caso «cliente sin cuentas» se prueba aunque el banco demo siempre traiga dos.
