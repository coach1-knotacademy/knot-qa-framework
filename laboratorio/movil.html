Qué es Appium: cuatro piezas

En Playwright, el código de la prueba y quien maneja el navegador vienen juntos. En Appium son programas separados que se hablan por la red. Por eso se abren dos terminales: una para el servidor y otra para las pruebas.

El código, capa por capa

Esto es el código real del kit, leído de los archivos. Fíjate en que la prueba no tiene ni un localizador: están en el Page Object.

src/paginas/PaginaLogin.ts · el Page Object

import { $ } from '@wdio/globals';
import { PaginaBase } from './PaginaBase';
import { porAccesibilidad, porId } from './localizadores';
import type { Usuario } from '../datos/usuarios';

/**
 * PAGE OBJECT de la pantalla de inicio de sesión.
 * La prueba dice QUÉ hace el cliente (entrarCon); aquí está el CÓMO (qué tocar y en qué orden).
 */
export class PaginaLogin extends PaginaBase {
  // Peldaño 2 (resource-id): el título y los campos no tienen content-desc en esta app.
  get titulo() {
    return $(porId('loginTV'));
  }

  get campoUsuario() {
    return $(porId('nameET'));
  }

  get campoClave() {
    return $(porId('passwordET'));
  }

  // Peldaño 1 (accessibility id): el botón sí lo tiene. Se usa aunque el texto diga "Login".
  get botonEntrar() {
    return $(porAccesibilidad('Tap to login with given credentials'));
  }

  // Peldaño 2: los mensajes de error, uno debajo de cada campo.
  get errorDelUsuario() {
    return $(porId('nameErrorTV'));
  }

  get errorDeLaClave() {
    return $(porId('passwordErrorTV'));
  }

  async esperarQueCargue(): Promise<void> {
    await this.campoUsuario.waitForDisplayed();
  }

  async entrarCon(usuario: Usuario): Promise<void> {
    await this.campoUsuario.setValue(usuario.correo);
    await this.campoClave.setValue(usuario.clave);
    await this.botonEntrar.click();
  }
}

tests/tienda.spec.ts · el CP-402, un paso() por línea del Gherkin

it('@CP-402 Un usuario bloqueado no puede entrar', async () => {
  await paso('Dado que el usuario bloqueado abre la pantalla de inicio de sesión', async () => {
    await menu.irAIniciarSesion();
    await login.esperarQueCargue();
  });
  await paso('Cuando entra con su correo y su clave', async () => {
    await login.entrarCon(usuarios.bloqueado);
  });
  await paso('Entonces ve el mensaje «Sorry this user has been locked out.»', async () => {
    await expect(login.errorDeLaClave).toHaveText('Sorry this user has been locked out.');
  });
  await paso('Y sigue en la pantalla «Login»', async () => {
    await expect(login.titulo).toHaveText('Login');
  });
});

paso() es el test.step de Playwright escrito a mano: imprime la línea del Gherkin en el reporte y deja su captura. expect(…).toHaveText(…) reintenta solo hasta que el texto aparece, igual que en Playwright.

La escalera de localizadores móviles

La misma idea de la S6: se sube un peldaño solo si el de abajo no existe en esa pantalla.

  1. 1
    Accessibility id (content-desc) · ~Tap to login with given credentials
    Siempre que exista: lo pone el desarrollador a propósito y no cambia con el diseño. Es el getByRole del móvil.
  2. 2
    resource-id · id=com.saucelabs.mydemoapp.android:id/nameET
    Si no hay accessibility id (los campos de esta app). Estable, pero es un nombre técnico.
  3. 3
    UiAutomator · android=new UiSelector().text("Sauce Labs Backpack")
    Cuando lo único que distingue al elemento es su texto (un producto en una lista).
  4. 4
    XPath
    Nunca. Es lento en móvil y se rompe con cualquier cambio. Si no hay peldaño 1-3, se le pide un content-desc al equipo de desarrollo.

Un error real que se corrigió: el proyecto Java anterior buscaba //*[contains(text(),'Login')]. En UiAutomator2 eso no encuentra nada, porque en Android el texto es un atributo (@text), no un nodo de texto como en HTML. El reemplazo es el peldaño 3: new UiSelector().text("Login").

¿Cómo ver qué tiene cada elemento? Con Appium Inspector (está en la guía) o con await driver.getPageSource(), que devuelve el árbol de la pantalla con text, content-desc y resource-id.

Para quién es, y el plan B

plan A · correrlo

Para quien tiene permisos de administrador (o un equipo que TI ya preparó): hay que instalar Android Studio y tener la virtualización encendida. Con buena red, de 1 a 2 horas.

  1. Lee primero el paso 0 de la guía: virtualización, VDI, proxy y antivirus. Si alguno está cerrado, se le pide a TI.
  2. Sigue la guía con las versiones fijadas.
  3. npm.cmd run appium en una terminal y npm.cmd test en otra.

Guía de instalación en Windows README del kit

La guía trae prompts listos para tu Copilot («pega la salida de appium driver doctor…»). Nunca pegues datos del banco.

plan B · sin instalar nada

Igual de válido. El 80 % de lo que enseña el kit se aprende leyendo:

  1. Mira el video y las capturas de la corrida.
  2. Lee el Page Object y la prueba y ubica cada localizador en la escalera.
  3. Compara con la Rosetta: ¿cómo se vería en Java?
  4. Escribe en Gherkin un caso móvil de tu trabajo (sin datos reales) con el mismo formato de tienda.feature.

Las nubes de dispositivos (BrowserStack, Sauce Labs) piden cuenta: solo si tu empresa ya las contrata.
