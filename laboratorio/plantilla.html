La plantilla de tu framework

Un framework mínimo y propio, con las mismas capas del knot-qa-framework: configuración, páginas, datos, flujos, soporte y pruebas. Corre contra el Banco Demo publicado; no hace falta levantar ningún servidor.

Les prometí un repo aparte; como no todos pueden clonar, aquí está en una página que sí abren. Quien tenga GitHub la encuentra en plantilla/ del proyecto.

Antes de usarla, dos reglas

Solo sitios de práctica

  • Solo Banco Demo o ParaBank; nunca sistemas, datos, pantallas ni casos del ALM del banco.
  • Al prompt, a Copilot o a cualquier IA no se le pegan casos, capturas, logs ni datos del trabajo. Para practicar, los CP-101 a CP-106 del Banco Demo.
  • La clave nunca va en el código: llega por la terminal ($env:CLAVE_BANCO) y el .env no se sube.

Lo que la IA escribe se lee antes de correrlo

  • Se revisa con la lista de cotejo, línea por línea, antes de la primera corrida.
  • Si una prueba falla, no se cambia la aserción para que pase: primero se averigua si es un defecto.
  • Al final, pídele que liste lo que supuso, y confírmalo con la regla de negocio.

El prompt para tu Copilot

Copia el prompt (desde «Actúa como» hasta el final) y reemplaza solo lo que está entre [corchetes]. Funciona aunque tu Copilot no vea el proyecto: todo lo que necesita saber va adentro.

## Estructura del framework

```
src/config/ambientes.ts   catálogo de ambientes (demo, qa, uat); producción bloqueada; congelado
src/config/entorno.ts     la configuración de la corrida: entorno.urlBase, entorno.usuario, entorno.clave
src/paginas/              un Page Object por pantalla; los localizadores viven SOLO aquí, sin expect
src/datos/                fábricas de datos de prueba con nombres de negocio
src/flujos/sesion.ts      abrirConSesion(page): deja la sesión abierta sin pasar por el ingreso
src/soporte/fixtures.ts   entrega las piezas a cada prueba (test y expect se importan de aquí)
tests/                    una prueba por caso, con el ID del caso en el nombre (CP-101 · ...)
```

## Reglas

1. **Localizadores por rol o por etiqueta**, en este orden: `getByRole(rol, { name })`, `getByLabel`, `getByText`, `getByTestId`. Nunca CSS, XPath, clases, id ni posiciones (`nth-child`). Si un elemento no tiene rol, etiqueta ni texto que sirva, NO inventes un selector: escribe `// TODO: pedir a desarrollo un data-testid para <elemento>` y dímelo al final.
2. **Los localizadores van en el Page Object**, como `private readonly`, nunca en la prueba. Si la pantalla no tiene Page Object, créalo con la forma del ejemplo de abajo (hereda de `PaginaBase`, su `ruta` es relativa) y agrégalo en `src/soporte/fixtures.ts`.
3. **La URL sale de `entorno`.** Usa rutas relativas (`recargas.html`). Nunca una dirección completa en la prueba ni en el Page Object.
4. **Sin claves.** Nunca escribas una clave, un token ni un usuario real. El usuario y la clave salen de `entorno` (y `abrirConSesion` ya los usa).
5. **Sin pausas fijas.** Nada de `waitForTimeout` ni `setTimeout`. Espera con `expect(...).toHaveText(...)`, `toBeVisible()` o `locator.waitFor()`.
6. **Sin librerías nuevas.** Solo `@playwright/test` y `typescript`. Si algo parece necesitar otra, dilo en un comentario y no la instales.
7. **Datos desde una fábrica** (`src/datos/`), cambiando solo lo que le importa al caso. Nunca datos reales.
8. **El esperado sale de la regla de negocio, no de la pantalla.** Si no conoces el resultado esperado, no lo copies de lo que muestra el sitio: escribe `// TODO: confirmar con la regla` en esa línea.
9. **No cambies una aserción para que la prueba pase.** Si crees que el sitio está mal, deja la aserción con el valor correcto y explícalo: puede ser un bug.
10. **Todo en español**: nombres de métodos, comentarios y el título de la prueba, que empieza con el ID del caso.

## Ejemplo de Page Object (cópiale la forma)

`src/paginas/PaginaRecargas.ts`

```ts
import { Locator, Page } from '@playwright/test';
import { Recarga } from '../datos/fabricaDeRecargas';
import { PaginaBase } from './PaginaBase';

/**
 * PAGE OBJECT · Pantalla "Recargar celular" del Banco Demo.
 *
 * La prueba dice QUÉ ("recarga esto"); esta clase sabe CÓMO. Los localizadores siguen la escalera:
 *   rol + nombre → etiqueta → texto visible → data-testid pactado → (CSS o XPath: nunca)
 * Por eso aguantan el rediseño de la pantalla (recargas.html?rediseno=1): cambian los id, las clases
 * y el orden, pero no lo que ve el usuario.
 */
export class PaginaRecargas extends PaginaBase {
  readonly ruta = 'recargas.html';
  /** El saldo no tiene etiqueta ni rol propio: se usa el data-testid que se pactó con desarrollo. */
  readonly saldoDisponible: Locator;
  readonly comprobante: Locator;
  private readonly listaOperador: Locator;
  private readonly campoNumero: Locator;
  private readonly campoValor: Locator;
  private readonly botonRecargar: Locator;

  constructor(page: Page) {
    super(page);
    this.saldoDisponible = page.getByTestId('saldo-disponible');
    this.comprobante = page.getByRole('status');
    this.listaOperador = page.getByLabel('Operador');
    this.campoNumero = page.getByLabel('Número de celular');
    this.campoValor = page.getByLabel('Valor de la recarga');
    this.botonRecargar = page.getByRole('button', { name: 'Recargar' });
  }

  /** Llena el formulario y pulsa Recargar. */
  async recargar({ operador, numero, monto }: Recarga): Promise<void> {
    await this.listaOperador.selectOption(operador);
    await this.campoNumero.fill(numero);
    await this.campoValor.fill(String(monto));
    await this.botonRecargar.click();
  }

  /** Espera la respuesta (sin pausas fijas) y devuelve el texto del comprobante o del error. */
  async esperarResultado(): Promise<string> {
    const resultado = this.comprobante.or(this.mensajeDeError);
    await resultado.waitFor();
    return (await resultado.innerText()).trim();
  }
}
```

## Cómo usarla (Windows PowerShell)

1. Copia la carpeta `plantilla` a un lugar **fuera de OneDrive** y ábrela en VS Code.
2. En la terminal de VS Code, dentro de esa carpeta:

   ```powershell
   npm.cmd install
   npx.cmd playwright install chromium
   npm.cmd test
   ```

   Si tu equipo no deja descargar Chromium, usa el Edge instalado en lugar del segundo comando:

   ```powershell
   $env:PW_CHANNEL = 'msedge'
   npm.cmd test
   ```

3. El reporte: `npm.cmd run reporte`. Arriba dice contra qué ambiente se corrió.

Si `npm.cmd install` no funciona en tu equipo (sin acceso al registro de paquetes), no insistas: usa la [página de la plantilla](https://coach1-knotacademy.github.io/knot-qa-framework/plantilla.html) para leer y copiar los archivos, y practica en el laboratorio de la S6.

## Ambientes

Sin variables se usa `demo`. Para otro ambiente, solo en esa ventana:

```powershell
$env:AMBIENTE = 'qa'
$env:CLAVE_BANCO = '...'
npm.cmd test
```

- `qa` y `uat` tienen direcciones de ejemplo (`.ejemplo`): cámbialas en `src/config/ambientes.ts` por las de tu proyecto. **Nunca agregues producción.**
- Fuera de `demo`, si falta `CLAVE_BANCO` la corrida se detiene de inmediato y dice qué hacer.
- Cualquier ambiente que no esté en el catálogo (`produccion`, `prod`…) se bloquea.
- Si prefieres un archivo, copia `.env.ejemplo` como `.env` y llénalo. El `.env` nunca se sube (está en `.gitignore`).

Catálogo de ambientes, producción bloqueada, configuración congelada · 60 líneas

/**
 * CAPA DE CONFIGURACIÓN · LOS AMBIENTES (S6)
 *
 * Como los "environments" de Postman: la misma suite, contra otro ambiente, sin tocar las pruebas.
 * Tres controles de un banco real:
 *   1. Solo se aceptan los ambientes del catálogo: producción queda BLOQUEADA (lista blanca).
 *   2. Fuera del ambiente de práctica, la clave llega por la terminal y, si falta, se falla DE INMEDIATO.
 *   3. La configuración queda CONGELADA (Object.freeze): nadie la cambia a mitad de la corrida.
 *
 * Para tu proyecto: cambia las direcciones de qa y uat por las de tu sistema (nunca la de producción).
 */

export type NombreDeAmbiente = 'demo' | 'qa' | 'uat';

export interface Ambiente {
  nombre: NombreDeAmbiente;
  urlBase: string;
  usuario: string;
  clave: string;
}

/** Las variables de la terminal (process.env) o, en una prueba, un objeto que las simula. */
export type Variables = Record<string, string | undefined>;

/**
 * EL CATÁLOGO. "demo" es el Banco Demo publicado en GitHub Pages: corre sin instalar un servidor.
 * La dirección termina en "/" para que las rutas relativas (recargas.html) funcionen.
 * Las de qa y uat son FICTICIAS (.ejemplo no existe): reemplázalas por las de tu proyecto.
 */
export const catalogoDeAmbientes: Record<NombreDeAmbiente, { urlBase: string; usuario: string }> = {
  demo: { urlBase: 'https://coach1-knotacademy.github.io/knot-qa-framework/banco/', usuario: 'ana' },
  qa: { urlBase: 'https://qa.mi-proyecto.ejemplo/', usuario: 'usuario-de-pruebas' },
  uat: { urlBase: 'https://uat.mi-proyecto.ejemplo/', usuario: 'usuario-de-pruebas' },
};

/** La clave del Banco Demo es pública (está escrita en su pantalla de ingreso). Solo vale para "demo". */
const CLAVE_DE_PRACTICA = 'Clave123';

/** Lee una variable. Vacía cuenta como que no está. */
export function leer(variables: Variables, nombre: string): string | undefined {
  const valor = variables[nombre]?.trim();
  return valor ? valor : undefined;
}

export function configurarAmbiente(nombre: string, variables: Variables = {}): Readonly<Ambiente> {
  if (!Object.keys(catalogoDeAmbientes).includes(nombre)) {
    throw new Error(`Ambiente "${nombre}" bloqueado. Este framework no corre contra producción ni contra ambientes que no conoce. Usa demo, qa o uat.`);
  }
  const ambiente = nombre as NombreDeAmbiente;

  const clave = ambiente === 'demo' ? leer(variables, 'CLAVE_BANCO') ?? CLAVE_DE_PRACTICA : leer(variables, 'CLAVE_BANCO');
  if (!clave) throw new Error(`Falta CLAVE_BANCO para el ambiente ${ambiente}. Defínela en la terminal: $env:CLAVE_BANCO = '...'`);

  return Object.freeze({
    nombre: ambiente,
    urlBase: leer(variables, 'URL_BANCO') ?? catalogoDeAmbientes[ambiente].urlBase,
    usuario: leer(variables, 'USUARIO_BANCO') ?? catalogoDeAmbientes[ambiente].usuario,
    clave,
  });
}

plantilla/src/paginas/PaginaBase.ts

Lo que tienen en común todas las pantallas · 21 líneas

import { Locator, Page } from '@playwright/test';

/**
 * CLASE PADRE de todas las pantallas: lo que tienen en común.
 * Cada pantalla hija dice su ruta y hereda abrir() y el mensaje de error.
 */
export abstract class PaginaBase {
  /** El mensaje de error. Se busca por su rol (alert), no por su id ni su color. */
  readonly mensajeDeError: Locator;

  constructor(protected readonly page: Page) {
    this.mensajeDeError = page.getByRole('alert');
  }

  /** La ruta de la pantalla, RELATIVA a entorno.urlBase (por ejemplo "recargas.html"). Nunca la dirección completa. */
  abstract readonly ruta: string;

  async abrir(): Promise<void> {
    await this.page.goto(this.ruta);
  }
}

import { Page } from '@playwright/test';
import { entorno } from '../config/entorno';

/** Lo que responde el "servicio" del Banco Demo: un estado HTTP y el JSON (distinto en cada ruta). */
interface Respuesta {
  estado: number;
  datos: any;
}

/**
 * FLUJO: deja el navegador con la sesión abierta SIN pasar por las pantallas de ingreso.
 * Úsalo en las pruebas cuyo objetivo NO es el ingreso: son más rápidas y estables.
 *
 * En el Banco Demo de GitHub Pages no hay servidor: el "servicio" corre dentro de la misma página
 * (api-estatica.js). Por eso se le habla desde la página. En tu proyecto, aquí va tu cliente de API.
 */
export async function abrirConSesion(page: Page, usuario = entorno.usuario, clave = entorno.clave): Promise<void> {
  await page.goto('index.html');
  const error = await page.evaluate(async ({ usuario, clave }) => {
    const api = (window as unknown as { apiEstatica: (ruta: string, opciones?: { method: string; body: string }) => Promise<Respuesta> }).apiEstatica;
    const enviar = (ruta: string, cuerpo: object) => api(ruta, { method: 'POST', body: JSON.stringify(cuerpo) });

    const ingreso = await enviar('/api/login', { usuario, clave });
    if (ingreso.estado !== 200) return ingreso.datos.error ?? `Ingreso: estado ${ingreso.estado}`;
    const buzon = await api(`/api/buzon?usuario=${encodeURIComponent(usuario)}`);
    const codigo = await enviar('/api/otp', { idDesafio: ingreso.datos.idDesafio, codigo: buzon.datos[0]?.codigo });
    if (codigo.estado !== 200) return codigo.datos.error ?? `Código: estado ${codigo.estado}`;

    localStorage.setItem('token', String(codigo.datos.token));
    localStorage.setItem('nombre', String(codigo.datos.nombre));
    return null;
  }, { usuario, clave });
  if (error) throw new Error(`No se pudo abrir la sesión de ${usuario} en ${entorno.nombre}: ${error}`);
}
